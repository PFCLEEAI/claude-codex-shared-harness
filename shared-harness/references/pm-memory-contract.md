# PM Memory Contract

- Use `_pm/context.md` for current state, decisions, blockers, and next steps.
- Use `_pm/memory.md` for durable rules, gotchas, and setup notes.
- Use `_pm/checklist.md` for active execution status.
- Use `_pm/roadmap.md` for the milestone order and dependencies. Link milestones to the checklist.
- Use `_pm/work-log.md` for concise progress and verification notes.
- Use `_pm/contracts/` for scope and acceptance criteria.
- Use `_pm/handoffs/` for lane outputs.
- Read context and memory before broad exploration.
- After meaningful progress, update context and work-log. Mark checklist items as they complete.
- Handoffs should include changed paths, checks run, risks, and next steps.
- The coordinator owns project status and checklist updates. Workers report their own results in `_pm/handoffs/`.
- Follow the [PM coordinator runbook](pm-coordinator.md) to initialize, delegate, verify, and resume work.
